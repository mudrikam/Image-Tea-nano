# Adjusting the Parameters

Use the toolbar controls to set generation parameters. Changes are saved immediately to the application configuration and take effect for subsequent generation requests.

![Adjust Parameters](res/images/adjust_parameter.png)

Definite behavior of each parameter:

- **Min Title**: Requests the model to produce titles with at least this many characters.
- **Max Title**: Requests the model to produce titles with at most this many characters.
- **Max Desc**: Requests the model to produce descriptions with at most this many characters.
- **Tag Count**: Requests the model to generate exactly this number of keywords/tags for each file.
- **Batch Size**: Sets how many files are sent in a single API batch request. The maximum allowed value is 20.
- **Quality**: Sets the image cache quality (1–100) for files sent to the API.
  - `100` = original quality (no compression).
  - Lower values produce smaller cache files and reduce data usage; higher values preserve more image detail.
  - Recommended: `70–80`.
  - Important clarification: this setting only affects the size and visual detail of the image files sent to the AI service. Compression **does not** change the number of tokens counted by the API for text prompts or responses. Token usage is determined by the textual content (prompt + response) and the model's tokenizer, not by image file size. Very high compression can reduce visual detail, which will change what the model sees and can change the generated text, but it still does not alter token counts used by the request.
- **Delay (s)**: Sets the pause between batches.
  - `No Delay` = 0 seconds.
  - `Random` = random interval between 1 and 5 seconds.
  - A numeric value is treated as seconds between batches.
- **Proxy**: Controls video proxying for videos sent to the AI service.
  - `Off`: Do not generate a proxy; the original video file is used.
  - `Auto`: Create a proxy with a preset chosen automatically based on input resolution (>=1920 → High, >=1280 → Medium, otherwise Low).
  - `High` / `Medium` / `Low`: Create a proxy using a fixed preset (resolution, bitrate, CRF) to reduce upload size and speed processing.
  - Proxying changes the visual detail sent to the model and can affect generated metadata, but it does not change text token usage for API requests.

Editing proxy presets

You can edit the preset values (Label, Resolution, Bitrate, CRF) used for `Low` / `Medium` / `High` proxies via the Video Proxy Preset Editor. Open it from the application menu: Prompt → Video Proxy Settings.

![Video Proxy Preset Editor](res/images/video_proxy_preset_editor.png)

Field explanations and rules:
- **Label**: A short, human-readable name for the preset (for display only). Use plain text, keep it concise, and avoid line breaks.
- **Resolution**: FFmpeg `scale` format for the target size. Use either `WIDTH:-2` to preserve aspect ratio (recommended), or `WIDTH:HEIGHT` for an exact size. Examples: `1920:-2` (1080p target), `854:480` (explicit 480p). Do not include commas or units.
- **Bitrate**: Target video bitrate expressed as kbits with a trailing `k` (e.g. `2500k`, `1000k`). Do not include spaces. You may also use `M` for megabits (e.g. `2M`) if you prefer, but `k` is standard.
- **CRF**: Integer 0–51 (FFmpeg CRF value). Lower numbers mean higher quality (and larger files). Typical values: `18` (high quality), `23` (medium), `28` (low).

Notes:
- The editor saves the values to the application configuration when you click Save. Changes take effect on subsequent proxy generation operations.
- Use `Auto` proxy mode in the Prompt toolbar to let the application pick `Low`/`Medium`/`High` based on the input file resolution.
- Avoid invalid formats (e.g., `bitrate` without units or malformed `resolution`) as FFmpeg may fail or produce unexpected results.

Storage and validation:

- Parameter changes are persisted to the application configuration immediately.
- Controls enforce valid ranges (e.g., `Batch Size` ≤ 20; `Compression` between 1 and 100) to prevent invalid input.

These parameters control the length, quantity, batching, and data usage of metadata generation. Set them to produce titles, descriptions, and tags that meet your platform requirements and workflow needs. Changes apply to the next generation run.
