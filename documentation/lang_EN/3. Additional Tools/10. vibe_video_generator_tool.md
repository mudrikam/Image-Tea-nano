# Vibe Video Generator

Vibe Video Generator is an AI-powered tool that lets you create animated video scripts using TypeScript and React (powered by Remotion), generate them automatically from a text description, preview them inside the app, and render them to an actual video file — all in one place.

> **This tool requires a Member login.** You must be logged in to access it.

---

## Interface Overview

The window is divided into the following areas:

- **Menu bar** (top) — three menus: **Collection**, **Script**, and **Tools** for managing collections, scripts, and utilities
- **API Key section** (below menu bar) — compact area to select your AI provider and model for script generation and refinement
- **Left panel** — Collections tree with search, showing all your script collections and scripts in a hierarchical structure
- **Right panel** — tabbed area with four main tabs: **TypeScript** (code editor), **Preview** (Remotion Studio viewer), **Output** (render destination settings), and **Render Settings** (fine-tune video parameters)
- **Bottom bar** — two-tab widget: **Render** tab holds quick-render controls; **Render Queue** tab shows batch render progress

---

## Menu Bar

### Collection Menu

- **New Collection** (`Ctrl+Shift+N`) — opens a dialog to create a new top-level collection. Set name, description, icon, and color.
- **New Subfolder** — creates a sub-collection inside the currently selected collection.
- **New Script** (`Ctrl+N`) — opens the New Script dialog for the currently selected collection. If no collection is selected, you will be prompted to select one first.
- **Render This Collection** — starts a batch render of all scripts in the selected collection (including all sub-collections recursively). Uses the same render settings for every script. See **[Batch Render](#batch-render-render-collection)** below.
- **Rename Collection** — rename the selected collection and change its icon or color.
- **Delete Collection** — permanently delete the selected collection and all scripts within it (including sub-collections). A confirmation dialog shows what will be deleted.

### Script Menu

- **Edit Script** (`Ctrl+E`) — opens the Edit Script dialog for the currently selected script.
- **Rename Script** — rename the selected script.
- **Save as TSX** — export the selected script to a standalone `.tsx` file using a file save dialog.
- **Delete Script** — permanently delete the selected script. Confirmation required.

### Tools Menu

- **Export Collection to ZIP** — exports the selected collection (all scripts and sub-collections) into a ZIP archive, preserving folder hierarchy. Each script is saved as a `.tsx` file.

## Collections Panel (Left)

The left panel displays your scripts organized in a tree structure.

- **Search field** — at the top, type to filter collections and scripts by name, description, tags, or script content in real time. Matching items remain visible; parents auto-expand to show matches.
- **Tree items** — each collection shows an icon, name, and a badge with script and sub-collection counts. Scripts appear as numbered items (e.g., "1. My Script") beneath their collection.
- **Expand/Collapse** — click a collection to expand or collapse it. Expander arrows also appear on the right side of each item.
- **Selection** — click a collection to select it (highlights); click a script to load it into the TypeScript editor. Selection triggers are debounced to avoid rapid updates during navigation.
- **Context menu** — right-click any item for actions (see **Collections Context Menu** below).

The collections tree reflects the database state and updates automatically after create, rename, delete, or edit operations.

## Collections Context Menu

### Right-click on a Collection

- **New Collection** — create a new top-level collection
- **New Subfolder** — create a child collection inside this one
- **New Script** — create a new script inside this collection
- **Export to ZIP** — export this collection (with all scripts and sub-collections) to a ZIP file
- **Render This Collection** — start a batch render of every script in this collection tree. See **[Batch Render](#batch-render-render-collection)**.
- **Rename** — edit the collection's name, description, icon, or color
- **Delete** — permanently delete this collection and all its contents. A warning dialog lists all sub-collections and scripts that will be removed.

### Right-click on a Script

- **Edit Script** — open the script in the Edit Script dialog
- **Rename Script** — change the script's name
- **Save as TSX File** — save the script content to a `.tsx` file at a location you choose
- **Delete Script** — permanently delete this script. Confirmation required.

## New Script / Edit Script Dialog

Opens when you create a new script or edit an existing one. The dialog has two tabs:

### Generate with AI Tab

Use this tab to generate a complete TypeScript animation script from a text description.

1. **Description field** — type what you want the video to look like. Be as descriptive as you like. Examples:
   - *"A countdown from 10 to 0 with a glowing red background"*
   - *"The word SALE fades in with a bounce, then slides out to the right"*
2. **Refine Prompt** — if your idea is rough, click this button (or the star icon). The AI expands your description into a detailed, well-structured prompt automatically.
3. **Generate from Image** — click the image icon to open the **Image Prompt Generator** (see below). Analyze an image (from file, clipboard, or database) to produce a detailed animation prompt, which is then inserted into the description field.
4. **Generate Script** — sends your description to the AI and generates a TypeScript animation script using Remotion. On success, the code appears in the **TypeScript** tab automatically. Retries up to 5 times with exponential backoff on failure. Extracts code from markdown fences or raw response.

**Fields** (below tabs):
- **Script Name** — required. Becomes the file name when rendering.
- **Description** — optional short note about the script's purpose.
- **Save / Create** button — saves the script to the selected collection.

### TypeScript Tab

Displays the generated or manually written TypeScript/React code with full syntax highlighting and line numbers.

- Edit the code directly before saving.
- **Save** button writes changes to the database.

## TypeScript Tab (Main Editor)

The primary code editing area shows the currently selected script.

- **Load script** — select a script from the Collections panel; its content appears here.
- **Syntax highlighting** — TypeScript keywords, strings, comments, and operators are color-coded using a VS Code One Dark / One Light style theme that follows the system dark/light mode.
- **Line numbers** — displayed in the left gutter; click line numbers to select entire lines (Ctrl+click for multi-line selection, Shift+click for range selection).
- **Refine with AI** — field and button at the bottom of the editor. Type an instruction (e.g., *"make the text red"* or *"add a fade-out at the end"*) and click **Refine**. The AI applies targeted changes using SEARCH/REPLACE blocks to edit the existing code with minimal modifications. Retries up to 3 times on failure; a retry dialog appears if all attempts fail.
- **Clear** — clears the editor content (unsaved changes are not preserved; use Save first).
- **Save** — saves the current script content to the database.
- **Open in Browser** — launches a full Remotion Studio instance in your default browser for advanced editing and playback. The Studio runs on a local port and hot-reloads when you modify the script and wait ~1.5 seconds. The button is disabled while Studio is starting; retries up to 3 times on failure.

The editor is read-only when no script is selected.

## Preview Tab

Preview your animation directly inside the app using an embedded Remotion Studio webview.

- **Start Server** — compiles the current script and starts a local preview server. The first launch can take 10-30 seconds as dependencies are installed and the bundle builds. The embedded view appears once ready.
- **Stop** — stops the preview server and clears the webview.
- **Reload** — refreshes the preview to reflect any code changes made after the server started. Hot-reload automatically triggers on save; use Reload for manual refresh.
- **Open in Browser** — opens the same Remotion Studio preview in your default web browser for a larger, distraction-free view with full devtools.

**Behavior:**
- A script must be selected and have non-empty code before you can start the server.
- When you select a different script, the preview tab prepares for that script; click **Start Server** to load it.
- If the server fails to start (port busy, build error, etc.), the tool retries up to 3 times with increasing delays. After exhausting retries, an error dialog appears.
- The server auto-stops when you close the dialog.

## Output Tab

Configure where and how the rendered video will be saved.

- **Filename** — the output file name (without extension). Auto-fills from the script name when you select a script. The field sanitizes invalid characters and Windows reserved names automatically.
- **Output** — the folder path where the video will be saved. Three companion buttons:
  - **Browse** (`📁`) — opens a folder picker dialog
  - **Paste** (`📋`) — pastes a path from the clipboard
  - **Open** (`🔗`) — opens the current folder in Windows Explorer (or macOS Finder / Linux file manager)
- **Format** — the output file format. Options: `mp4`, `webm`, `mov`, `gif`, `png`, `jpg`, `mp3`, `wav`, `aac`.
- **Overwrite existing file** — when checked (default), replaces any existing file with the same name. Uncheck to prompt before overwriting (via render settings).
- **Output as image sequence** — renders each frame as a separate image file instead of a single video. Useful for frame-by-frame inspection or further compositing.
- **Mute audio** — renders the video without any audio track, even if the script contains audio components.
- **Enforce silent audio track** — forces an empty audio track to be included, even if the script has no audio. Some platforms require a silent track for proper duration handling.

Output filename and path are **auto-saved** between sessions in a temporary config file and stay synchronized with the bottom Render bar fields.

## Render Settings Tab

Fine-tune every aspect of video rendering. Settings are grouped into collapsible sections and auto-saved to a custom preset whenever you modify them while on the "custom" preset.

### Preset

Quick-select dropdown to load a set of predefined configuration bundles:

| Preset | Resolution | FPS |
|-------|-----------|-----|
| 720p30 | 1280 × 720 | 30 |
| 1080p60 | 1920 × 1080 | 60 |
| 2K60 | 2560 × 1440 | 60 |
| 4K60 | 3840 × 2160 | 60 |

- **Save** — saves the current settings as a named Custom preset. Enter a preset name in the dialog; it is added to the dropdown for future recall.
- **Reset** — reverts all settings back to the 1080p60 preset.

### Video Settings

- **Width / Height** — output resolution in pixels. `0` or `Auto` means width follows the script's `useVideoConfig().width` (or height) automatically.
- **FPS** — frames per second. `0` or `Auto` uses the script's `useVideoConfig().fps`.
- **Duration** — total length in seconds. This **overrides** the duration defined in the script. Useful for extending or trimming the render without editing code.
- **Codec** — video encoder: `h264` (widely compatible), `h265` (better compression), `av1` (latest open codec), `vp8`/`vp9` (WebM), `prores` (professional editing), `h264-mkv` (Matroska container).
- **Pixel Format** — pixel encoding: `yuv420p` (default, universal), `yuv422p` (higher chroma), `yuv444p` (full chroma), or alpha-including variants `yuva420p`, `yuva422p`, `yuva444p`.
- **Scale** — scale factor applied after rendering (e.g., `0.5` for half resolution, `2.0` for double). Applied after all other processing.
- **Image Format** — intermediate frame format used during the rendering pipeline: `png` (lossless, slower) or `jpeg` (lossy, faster). PNG is recommended for animations with sharp edges or text.
- **Output as image sequence** — render each frame as an individual image file (PNG or JPEG based on Image Format) into the output folder instead of encoding a video. Use for frame-perfect compositing or debugging.
- **Frames** — comma-separated frame ranges to render, e.g., `0-100`, `200-300`, `0-50,100-150`. Only these frames are processed.
- **Every Nth Frame** — render every Nth frame only (e.g., `5` renders frames 0, 5, 10, ...). Speeds up previews.

### Audio Settings

- **Audio Codec** — `aac` (default, widely compatible), `mp3`, `wav` (uncompressed), `opus` (high efficiency).
- **Audio Bitrate** — target audio quality in kilobits per second (e.g., `128k`, `192k`, `256k`).
- **Mute audio** — disables audio entirely in the output.
- **Enforce silent audio track** — adds an empty audio track even when the script produces no audio. Some video platforms require a track for duration synchronization.
- **Separate Audio To** — path to a file where the audio stream will be saved separately (muxing into a separate file).
- **For seamless AAC concatenation** — applies special AAC settings to avoid gaps when concatenating multiple rendered files in a video editor.

### Quality Settings

- **CRF** — Constant Rate Factor for quality-based encoding (0 = lossless, 51 = worst). Leave at `Auto` (0) to let FFmpeg choose.
- **Video Bitrate** — target bitrate like `5M`, `10M`, `20M`. Overrides CRF when set.
- **Buffer Size** — decoder buffer size (e.g., `10M`).
- **Max Rate** — maximum bitrate ceiling (e.g., `5M`).
- **JPEG Quality** — 0-100 when Image Format is JPEG (default 80). Higher = better quality, larger files.
- **ProRes Profile** — `auto`, `4444` (highest quality with alpha), `4444-xq`, `hq`, `standard`, `light`, `proxy`.
- **x264 Preset** — encoding speed vs compression trade-off: `ultrafast` (least compression, largest files) to `veryslow` (best compression, slowest).
- **GIF Loops** — number of iterations for GIF output (`0` = infinite loop).

### Performance Settings

- **Concurrency** — number of parallel threads for rendering (1–256). `Auto` (0) uses CPU core count. Higher values increase speed but use more RAM and CPU. Recommended: 2–4 for 1080p, less for higher resolutions.
- **Hardware Acceleration** — `if-possible` (auto-detect and use GPU if available), `disabled` (CPU only), `required` (fails if no GPU).
- **Disallow parallel encoding** — force sequential frame encoding (useful for memory-limited systems or debugging).

### Browser Settings

These control the headless browser Remotion uses to capture frames:

- **Browser Executable** — path to a specific browser binary (Chrome/Chromium). Leave empty to use the system default or auto-detect.
- **Chrome Mode** — `default` (regular Chrome), `custom` (use your executable path), `launch` (new instance with clean profile).
- **Timeout** — server and navigation timeout in milliseconds (default 30000).
- **Ignore certificate errors** — bypass SSL warnings when loading remote resources.
- **Disable web security** — relax same-origin policy (needed for some cross-origin assets).
- **Disable headless mode** — run browser with a visible window (debugging only; slower).
- **Enable dark mode** — forces dark theme in the browser context.
- **User Agent** — custom user agent string if you need to spoof a specific browser.
- **GL Backend** — `default`, `egl`, `angle`, `swiftshader`, `gles`. Affects GPU rendering; change only if you encounter GPU driver issues.

### Advanced Settings

- **Config File** — path to a custom Remotion configuration file (`.ts`/`.js`/`.json`).
- **Env File** — path to a `.env` file loaded into the rendering environment.
- **Props File** — JSON file whose contents are passed as props to your composition.
- **Enable bundle cache** — caches the webpack bundle between runs (enabled by default; speeds up subsequent renders).
- **Log Level** — verbosity of Remotion logs: `error`, `warn`, `info`, `verbose`.
- **Port** — local port for the Remotion server (`0` = auto-select).
- **Public Directory** — path to a folder of static assets to serve.
- **Media Cache Size** — cache size for media files in bytes (e.g., `1000000000`).
- **OffthreadVideo Cache** — cache size for off-main-thread video decoding in bytes.
- **OffthreadVideo Threads** — number of threads for video decoding (1–128).
- **Enable multiprocess on Linux** — use multiprocess mode for better performance on Linux.
- **Generate repro** — generates a reproducible build folder for debugging.
- **Binaries Directory** — path to custom Remotion binaries.
- **Enable experimental Rspack** — opt into Rspack bundler (faster, experimental).
- **Metadata** — JSON string of arbitrary metadata embedded in the output.
- **Color Space** — `default`, `srgb`, `rec2020`, `display-p3`.
- **Image Sequence Pattern** — filename pattern for image sequences, e.g., `frame-%04d.png`.

**Note:** Most of these are advanced; the built-in presets cover typical use cases. Unnecessary changes can degrade performance or compatibility.

## Render Bar (Bottom)

The bottom section contains a two-tab widget for rendering control.

### Render Tab

Quick-access controls that mirror fields from the Output and Render Settings tabs:

- **Preset** — dropdown to switch render presets (720p30, 1080p60, 2K60, 4K60, Custom). Changes are reflected immediately in the Render Settings tab.
- **Duration** — spin box in seconds. This value overrides the duration set in the Render Settings tab for this render only. Synchronizes both ways.
- **Filename** — output file name (without extension). Stays in sync with the Output tab. Invalid characters are sanitized automatically.
- **Output** — output folder path. Stays in sync with the Output tab. Use the **Browse** (`📁`) button to pick a folder.
- **Progress bar** — displays render progress as a percentage and status message (e.g., "Encoding... 45%").
- **Render Video** — starts rendering the currently open script using the configured output and render settings. While rendering, the button changes to **Cancel** (red styling); clicking aborts the render. The UI disables most controls during rendering to prevent state conflicts.

**Render workflow:** The button triggers a single script render unless a batch render is active. If a batch render is running (started via **Render This Collection**), this button becomes **Cancel Batch** and stops the entire queue after the current script finishes.

### Render Queue Tab

Visible only during a batch render (Render Collection). Shows compact live progress of all queued scripts:

- **Stats label** — `Queue: X/Y | OK: N | Failed: M` where X is completed+failed+cancelled, Y is total.
- **Current script** — displays `collection / script_name [resolution fps duration codec]`
- **Progress bar** — per-script progress percentage and status message (Starting..., Encoding..., Completed, Failed, Cancelled).

Below the progress bar is a minimal **Render Queue** legend showing the same stats. The tab updates in real-time as each script finishes.

When all scripts complete, a **Batch Render Summary** dialog appears with a table of all results (Script, Status, Output/Error, Duration) and **Copy Report** button to copy a text summary to the clipboard.

## Batch Render (Render This Collection)

Batch rendering processes every script in a selected collection and all its sub-colclusions recursively, using the same render settings for all.

**How to start:**
1. Select a collection in the left panel.
2. Either right-click → **Render This Collection**, or use the Collection menu → **Render This Collection**.
3. A confirmation dialog shows total script count, preset, duration, format, and output folder.
4. Click **Yes** to begin.

**Behavior:**
- The tool creates a subfolder named after the collection inside your chosen output folder. Each script is saved as `001_script_name.mp4` (numbering preserves alphabetical order within each collection level).
- All scripts use the preset, duration, output format, and output folder settings currently shown in the bottom Render bar.
- The UI automatically switches to the **Render Queue** tab. The currently rendering script is **highlighted in the Collections tree** (primary color background) for easy identification.
- You can **Cancel** at any time via the red **Cancel** button in the bottom bar. Cancellation stops after the current script finishes.
- When complete, a **Batch Render Summary** dialog shows per-script status (OK, Failed, Cancelled) with timestamps and error snippets. Click **Copy Report** to copy a plain-text summary.

All individual script renders use the same error-fix and auto-retry logic as single renders.

## AI Features

### Generate Script from Description

The core AI feature: describe a video in natural language, and the tool generates a complete, valid Remotion TypeScript component.

- Uses your configured AI service (OpenAI, Gemini, Groq, etc.) with the system prompt enforcing Remotion best practices.
- Retries up to 5 times with exponential backoff (2s, 4s, 8s, 16s, 32s).
- Extracts code from markdown fences (```tsx ... ```) or plain text. Validates that the result contains `import` or `React` keywords; otherwise retries.
- On success, the code populates the TypeScript editor automatically.

### Refine Prompt

Located in the **Generate with AI** tab. Expands a short, rough idea into a detailed, structured prompt that yields better generated scripts. The AI rewrite is 3–6 sentences long and includes specifics on motion, colors, transitions, and mood. This is a separate AI call before generation.

### Refine Script (AI Code Edit)

In the TypeScript tab, type an instruction into the **Refine** field and click **Refine** (or press Enter). The AI reads your current script and makes a minimal, targeted change using SEARCH/REPLACE blocks. Only the affected lines are replaced; the rest of the script stays intact. Retries up to 3 times. If all attempts fail, a **Refine Failed** dialog lets you retry or cancel.

**Example instructions:**
- `make the text red`
- `add a fade-out at the end`
- `change the easing to spring`

### Fix Errors (AI Debug)

When a render fails due to a TypeScript or runtime error, a **Render Failed** dialog appears with the full error message. If an AI key is configured, a **Fix Errors** button is shown. Clicking it sends the script and the error to the AI, which attempts to patch the code automatically using SEARCH/REPLACE blocks. If the AI fix also fails, you can retry or manually edit.

## Export and Save Options

### Export Collection to ZIP

Exports an entire collection tree (collections, sub-collections, and all scripts) to a single ZIP archive. Each script is saved as a `.tsx` file with the same filename used in the database. The folder hierarchy inside the ZIP mirrors your collection structure. A progress dialog shows export status; cancellation is supported. The ZIP is written to a location you choose.

### Save Script as TSX

Exports a single script to a standalone `.tsx` file. Available from the Script menu and the script context menu. Opens a standard Save File dialog. This is useful for version-controlling scripts outside the app or sharing them.

## Tips

- **Keyboard shortcuts:** `Ctrl+Shift+N` for new collection, `Ctrl+N` for new script, `Ctrl+E` for edit script.
- **Search quickly:** Use the search field in the Collections panel to filter by name, tag, or even code content across all your scripts.
- **Preset workflow:** Stick to the built-in presets (720p60, 1080p60) for most use cases. Create a Custom preset only when you need specific codec or quality settings that differ significantly.
- **Batch rendering:** Use **Export to ZIP** first if you want a local backup before a large batch render. The batch render process highlights the currently rendering script in the tree, so you can track progress.
- **Preview hot-reload:** While the embedded preview server is running, saving the script (`Ctrl+S`) automatically triggers a hot-reload. You can also click **Reload** manually.
- **AI refinement:** The **Refine Prompt** button often produces better results than writing a prompt yourself. Use it even when you have a clear idea — the AI may add useful motion details you didn't consider.
- **Error recovery:** If **Fix Errors** fails, click the error dialog's **Retry** button. The AI re-attempts the fix using the updated script. Often a second or third attempt succeeds.
