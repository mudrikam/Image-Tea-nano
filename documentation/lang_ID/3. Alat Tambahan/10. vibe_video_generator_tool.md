# Vibe Video Generator

Vibe Video Generator adalah alat berbasis AI yang memungkinkan kamu membuat skrip animasi video menggunakan TypeScript dan React (didukung oleh Remotion), menghasilkan skrip secara otomatis dari deskripsi teks, melihat pratinjau langsung di dalam aplikasi, dan merendernya menjadi file video nyata — semuanya dalam satu tempat.

> **Alat ini membutuhkan login Member.** Kamu harus sudah login untuk mengaksesnya.

---

## Gambaran Antarmuka

Jendela dibagi menjadi area-area berikut:

- **Menu bar** (atas) — tiga menu: **Collection**, **Script**, dan **Tools** untuk mengelola koleksi, skrip, dan utilitas
- **Bagian API Key** (di bawah menu bar) — area compact untuk memilih provider AI dan model yang digunakan dalam generasi skrip, penyempurnaan, dan perbaikan error
- **Panel kiri** — pohon Collections dengan search/filter, menampilkan semua koleksi dan skrip dalam struktur hierarkis
- **Panel kanan** — area bertab dengan empat tab utama: **TypeScript** (editor kode), **Preview** (viewer Remotion Studio), **Output** (pengaturan output render), dan **Render Settings** (pengaturan detail video)
- **Bar bawah** — widget dua-tab: tab **Render** berisi kontrol render cepat; tab **Render Queue** menampilkan progress batch render

---

## Menu Bar

### Menu Collection

- **New Collection** (`Ctrl+Shift+N`) — membuka dialog untuk membuat koleksi top-level baru. Set nama, deskripsi, ikon, dan warna.
- **New Subfolder** — membuat sub-koleksi di dalam koleksi yang sedang dipilih.
- **New Script** (`Ctrl+N`) — membuka dialog New Script untuk koleksi yang sedang dipilih. Jika tidak ada koleksi terpilih, kamu akan diminta memilih koleksi terlebih dahulu.
- **Render This Collection** — memulai batch render semua skrip dalam koleksi yang dipilih (termasuk semua sub-koleksi secara rekursif). Menggunakan pengaturan render yang sama untuk semua skrip. Lihat **[Batch Render (Render This Collection)](#batch-render-render-this-collection)** di bawah.
- **Rename Collection** — mengubah nama koleksi dan mengatur ulang ikon atau warnanya.
- **Delete Collection** — menghapus permanen koleksi yang dipilih beserta semua isinya (termasuk sub-koleksi). Dialog konfirmasi akan menampilkan daftar item yang akan dihapus.

### Menu Script

- **Edit Script** (`Ctrl+E`) — membuka dialog Edit Script untuk skrip yang sedang dipilih.
- **Rename Script** — mengganti nama skrip.
- **Save as TSX** — mengekspor skrip ke file `.tsx` mandiri melalui dialog Simpan Berkas.
- **Delete Script** — menghapus permanen skrip. Konfirmasi diperlukan.

### Menu Tools

- **Export Collection to ZIP** — mengekspor koleksi yang dipilih (semua skrip dan sub-koleksi) ke arsip ZIP, mempertahankan struktur folder. Setiap skrip disimpan sebagai file `.tsx`.

## Collections Panel (Kiri)

Panel kiri menampilkan skrip yang diatur dalam struktur pohon.

- **Search field** — di bagian atas, ketik untuk memfilter koleksi dan skrip berdasarkan nama, deskripsi, tag, atau isi kode. Item yang cocok tetap terlihat; orangtua auto-expand untuk menampilkan hasil.
- **Tree items** — setiap koleksi menampilkan ikon, nama, dan badge dengan jumlah skrip dan sub-koleksi. Skrip muncul sebagai item bernomor (misal "1. My Script") di bawah koleksi induknya.
- **Expand/Collapse** — klik koleksi untuk membuka atau menutupnya. Panah expander juga tersedia di sisi kanan setiap item.
- **Selection** — klik koleksi untuk memilihnya (ter-highlight); klik skrip untuk memuatnya ke editor TypeScript. Event selection di-debounce untuk menghindari update berlebihan selama navigasi.
- **Context menu** — klik kanan item mana pun untuk akses cepat (lihat **Collections Context Menu** di bawah).

Collections tree merefleksikan state database dan otomatis di-refresh setelah create, rename, delete, atau edit.

## New Script / Edit Script Dialog

Munir saat membuat skrip baru atau mengedit yang sudah ada. Dialog memiliki dua tab:

### Tab Generate with AI

Gunakan tab ini untuk menghasilkan skrip TypeScript lengkap dari deskripsi teks.

1. **Description field** — ketaskan apa yang diinginkan untuk video. Sejelas mungkin. Contoh:
   - *"Countdown dari 10 ke 0 dengan latar belakang merah bercahaya"*
   - *"Kata SALE muncul dengan efek bounce, lalu meluncur keluar ke kanan"*
2. **Refine Prompt** — jika ide kamu kasar, klik tombol ini (atau ikon bintang). AI akan mengembangkan deskripsi menjadi prompt terperinci dan terstruktur secara otomatis.
3. **Generate from Image** — klik ikon gambar untuk membuka **Image Prompt Generator** (lihat di bawah). Analisis gambar (dari file, clipboard, atau database) untuk menghasilkan prompt animasi terperinci, yang kemudian dimasukkan ke field deskripsi.
4. **Generate Script** — kirim deskripsi ke AI dan hasilkan skrip animasi TypeScript menggunakan Remotion. Jika berhasil, kode muncul otomatis di tab **TypeScript**. Mencoba ulang hingga 5 kali dengan exponential backoff jika gagal. Mengekstrak kode dari markdown fence atau respons mentah.

**Field di bawah tab:**
- **Script Name** — wajib diisi. Menjadi nama file saat render.
- **Description** — opsional, catatan singkat tentang skrip.
- Tombol **Save / Create** — simpan skrip ke koleksi yang dipilih.

### Tab TypeScript

Menampilkan kode TypeScript/React dengan syntax highlighting dan line numbers.

- Edit kode langsung di sini sebelum menyimpan.
- Tombol **Save** menyimpan perubahan ke database.

## TypeScript Tab (Editor Utama)

Area penulisan kode utama yang menampilkan skrip yang sedang dipilih.

- **Memuat skrip** — pilih skrip dari panel Collections; kontennya muncul di sini.
- **Syntax highlighting** — keyword, string, comment, dan operator TypeScript diberi warna dengan tema One Dark / One Light (mengikuti mode gelap/terang sistem).
- **Line numbers** — angka baris di kiri gutter; klik nomor baris untuk memilih baris tersebut (Ctrl+click untuk multi-line, Shift+click untuk rentang).
- **Refine with AI** — field dan tombol di bawah editor. Masukkan instruksi (misal *"buat teks merah"* atau *"tambahkan fade-out di akhir"*) lalu klik **Refine**. AI melakukan perubahan ter targeting menggunakan blok SEARCH/REPLACE — hanya lines yang berubah yang diganti. Mencoba ulang hingga 3 kali; dialog retry muncul jika semua percobaan gagal.
- **Clear** — mengosongkan editor (perubahan belum disimpan tidak tersimpan; simpan dulu).
- **Save** — menyimpan konten skrip ke database.
- **Open in Browser** — meluncurkan instance Remotion Studio lengkap di browser default untuk editing dan preview lanjutan. Studio berjalan di port lokal dan hot-reload saat kamu ubah skrip dan menunggu ~1.5 detik. Tombol disabled saat Studio sedangStarting; mencoba ulang hingga 3 kali jika gagal.

Editor menjadi read-only ketika tidak ada skrip terpilih.

## Preview Tab

Preview animasi langsung di dalam aplikasi menggunakan embedded Remotion Studio webview.

- **Start Server** — mengkompilasi skrip aktif dan memulai server preview lokal. Pertama kali bisa memakan 10–30 detik karena instalasi dependency dan proses bundling. Tampilan embedded muncul setelah siap.
- **Stop** — menghentikan server preview dan membersihkan webview.
- **Reload** — me-refresh preview untuk mencerminkan perubahan kode yang dilakukan setelah server dimulai. Hot-reload terjadi otomatis saat kamu save; gunakan Reload untuk refresh manual.
- **Open in Browser** — membuka preview Remotion Studio yang sama di browser default untuk layar lebih besar dengan devtools lengkap.

**Perilaku:**
- Skrip harus terpilih dan memiliki kode non-kosong sebelum server dapat dimulai.
- Saat memilih skrip lain, Preview tab mempersiapkan skrip tersebut; klik **Start Server** untuk memuatnya.
- Jika server gagal dimulai (portUsed, build error, dll), tool mencoba ulang hingga 3 kali dengan delay bertambah. Dialog error muncul setelah retry habis.
- Server auto-stop saat dialog ditutup.

## Output Tab

Atur di mana dan bagaimana video hasil render akan disimpan.

- **Filename** — nama file output (tanpa ekstensi). Auto-isi dari nama skrip saat kamu memilih skrip. Field menyaring karakter invalid dan nama reserved Windows secara otomatis.
- **Output** — folder path tujuan video. Tiga tombol teman:
  - **Browse** (`📁`) — membuka dialog pilih folder
  - **Paste** (`📋`) — menempel path dari clipboard
  - **Open** (`🔗`) — membuka folder saat ini di Windows Explorer (atau macOS Finder / Linux file manager)
- **Format** — format file output. Opsi: `mp4`, `webm`, `mov`, `gif`, `png`, `jpg`, `mp3`, `wav`, `aac`.
- **Overwrite existing file** — jika dicentang (default), menggantikan file yang ada dengan nama sama. Uncheck untuk peringatan sebelum overwrite (via render settings).
- **Output as image sequence** — render setiap frame sebagai file gambar terpisah (bukan video). Berguna untuk inspeksi frame-by-frame atau compositing lanjutan.
- **Mute audio** — render video tanpa track audio, meski skrip mengandung komponen audio.
- **Enforce silent audio track** — memaksa tambahan track audio kosong meski skrip tidak menghasilkan audio. Beberapa platform memerlukan track untuk sinkronisasi durasi.

Filename dan path output **disimpan otomatis** antar-sesi di file config sementara dan tetap sinkron dengan field di bottom Render bar.

## Render Settings Tab

Sesuaikan setiap aspek rendering video. Settings dikelompokkan dan disimpan otomatis ke preset Custom setiap kali diubah saat preset "custom" aktif.

### Preset

Dropdown quick-select untuk memuat bundel konfigurasi yang sudah ditetapkan:

| Preset | Resolusi | FPS |
|-------|----------|-----|
| 720p30 | 1280 × 720 | 30 |
| 1080p60 | 1920 × 1080 | 60 |
| 2K60 | 2560 × 1440 | 60 |
| 4K60 | 3840 × 2160 | 60 |

- **Save** — simpan pengaturan saat ini sebagai preset Custom. Masukkan nama preset; ia ditambahkan ke dropdown untuk pengenalan di masa depan.
- **Reset** — kembalikan semua settings ke preset 1080p60.

### Video Settings

- **Width / Height** — resolusi output dalam pixel. `0` atau `Auto` berarti lebar mengikuti `useVideoConfig().width` (atau tinggi) dari skrip.
- **FPS** — frame per second. `0` atau `Auto` menggunakan `useVideoConfig().fps` skrip.
- **Duration** — durasi dalam detik. **Meng-override** duration yang didefinisikan di skrip. Berguna untuk memperpanjang atau memotong render tanpa mengedit kode.
- **Codec** — encoder video: `h264` (kompatibel luas), `h265` (kompresi lebih baik), `av1` (codec open terbaru), `vp8`/`vp9` (WebM), `prores` (proffesional editing), `h264-mkv` (container Matroska).
- **Pixel Format** — encoding pixel: `yuv420p` (default, universal), `yuv422p` (chroma lebih tinggi), `yuv444p` (full chroma), atau variant dengan alpha `yuva420p`, `yuva422p`, `yuva444p`.
- **Scale** — faktor skala yang diterapkan setelah render (misal `0.5` untuk setengah resolusi, `2.0` untuk ganda). Diterapkan setelah semua proses lain.
- **Image Format** — format frame intermediate saat rendering: `png` (lossless, lambat) atau `jpeg` (lossy, cepat). PNG disarankan untuk animasi dengan tepi tajam atau teks.
- **Output as image sequence** — render setiap frame sebagai file gambar terpisah ke folder output (bukan video). Berguna untuk compositing lanjutan atau debugging.
- **Frames** — rentang frame yang akan dirender, contoh: `0-100`, `200-300`, `0-50,100-150`. Hanya frame ini yang diproses.
- **Every Nth Frame** — render tiap N frame saja (misal `5` menghasilkan frame 0, 5, 10, ...). Mempercepat preview.

### Audio Settings

- **Audio Codec** — `aac` (default, kompatibel luas), `mp3`, `wav` (uncompressed), `opus` (efisiensi tinggi).
- **Audio Bitrate** — kualitas audio target dalam kbps (contoh `128k`, `192k`, `256k`).
- **Mute audio** — mematikan audio sepenuhnya.
- **Enforce silent audio track** — menambahkan track audio kosong meski skrip tidak menghasilkan audio. Beberapa platform video memerlukan track untuk sinkronisasi durasi.
- **Separate Audio To** — path ke file tersendiri di mana stream audio akan disimpan (muxing terpisah).
- **For seamless AAC concatenation** — mengatur AAC khusus untuk menghindari jeda saat menggabungkan beberapa file render di editor video.

### Quality Settings

- **CRF** — Constant Rate Factor untuk encoding berbasis kualitas (0 = lossless, 51 = terburuk). Biarkan `Auto` (0) agar FFmpeg memilih.
- **Video Bitrate** — bitrate target seperti `5M`, `10M`, `20M`. Meng-override CRF jika diisi.
- **Buffer Size** — ukuran buffer decoder (contoh `10M`).
- **Max Rate** — ceiling bitrate (contoh `5M`).
- **JPEG Quality** — 0-100 saat Image Format adalah JPEG (default 80). Lebih tinggi = kualitas lebih baik, file lebih besar.
- **ProRes Profile** — `auto`, `4444` (kualitas tertinggi dengan alpha), `4444-xq`, `hq`, `standard`, `light`, `proxy`.
- **x264 Preset** — trade-off kecepatan vs kompresi: `ultrafast` (kompresi sedikit, file besar) hingga `veryslow` (kompresi terbaik, paling lambat).
- **GIF Loops** — jumlah iterasi untuk output GIF (`0` = loop tak terbatas).

### Performance Settings

- **Concurrency** — jumlah thread paralel untuk rendering (1–256). `Auto` (0) menggunakan jumlah CPU core. Nilai lebih tinggi = lebih cepat tapi RAM & CPU lebih banyak. Rekomendasi: 2–4 untuk 1080p, lebih rendah untuk resolusi lebih tinggi.
- **Hardware Acceleration** — `if-possible` (auto-detect & pakai GPU jika ada), `disabled` (CPU saja), `required` (gagal jika tidak ada GPU).
- **Disallow parallel encoding** — paksa encoding frame sequential (berguna untuk sistem memory terbatas atau debugging).

### Browser Settings

Mengontrol browser headless yang digunakan Remotion untuk menangkap frame:

- **Browser Executable** — path ke binary browser spesifik (Chrome/Chromium). Kosongkan untuk pakai default sistem atau auto-detect.
- **Chrome Mode** — `default` (Chrome reguler), `custom` (gunakan path custom), `launch` (instance baru dengan profil bersih).
- **Timeout** — timeout server dan navigation dalam milidetik (default 30000).
- **Ignore certificate errors** — abaikan peringatan SSL saat memuat resource remote.
- **Disable web security** — melemahkan same-origin policy (diperlukan untuk beberapa asset lintas-origin).
- **Disable headless mode** —jalankan browser dengan window terlihat (debugging saja; lebih lambat).
- **Enable dark mode** — paksa tema gelap di konteks browser.
- **User Agent** — string user agent custom jika perlu spoof browser tertentu.
- **GL Backend** — `default`, `egl`, `angle`, `swiftshader`, `gles`. Memengaruhi rendering GPU; ubah hanya jika masalah driver GPU.

### Advanced Settings

- **Config File** — path ke konfigurasi Remotion custom (`.ts`/`.js`/`.json`).
- **Env File** — path ke file `.env` yang dimuat ke environment rendering.
- **Props File** — file JSON yang isinya dikirim sebagai props ke composition.
- **Enable bundle cache** — cache webpack bundle antar-runs (aktif default; mempercepat render berulang).
- **Log Level** — verbosity log Remotion: `error`, `warn`, `info`, `verbose`.
- **Port** — port lokal untuk server Remotion (`0` = auto-pilih).
- **Public Directory** — path ke folder static asset untuk dilayani.
- **Media Cache Size** — ukuran cache untuk file media dalam bytes (contoh `1000000000`).
- **OffthreadVideo Cache** — ukuran cache untuk decoding video off-main-thread dalam bytes.
- **OffthreadVideo Threads** — jumlah thread untuk decoding video (1–128).
- **Enable multiprocess on Linux** — pakai mode multiprocess untuk performa lebih baik di Linux.
- **Generate repro** — menghasilkan folder build reproducible untuk debugging.
- **Binaries Directory** — path ke binary Remotion custom.
- **Enable experimental Rspack** — opt-in ke bundler Rspack (lebih cepat, eksperimental).
- **Metadata** — JSON string metadata arbitrer yang disematkan ke output.
- **Color Space** — `default`, `srgb`, `rec2020`, `display-p3`.
- **Image Sequence Pattern** — pola nama file untuk image sequence, contoh: `frame-%04d.png`.

**Catatan:** Sebagian besar settings ini advanced; preset built-in cukup untuk kasus umum. Perubahan tidak perlu bisa menurunkan performa atau kompatibilitas.

## Render Bar (Bawah)

Bagian bawah berisi widget dua-tab untuk kontrol render.

### Render Tab

Control akses cepat yang mirror field dari tab Output dan Render Settings:

- **Preset** — dropdown untuk ganti preset render (720p30, 1080p60, 2K60, 4K60, Custom). Perubahan langsung tercermin di tab Render Settings.
- **Duration** — spin box dalam detik. Nilai ini **override** duration yang di-set di Render Settings untuk render ini saja. Sinkron dua arah.
- **Filename** — nama file output (tanpa ekstensi). Sinkron dengan tab Output. Karakter invalid disanitasi otomatis.
- **Output** — path folder output. Sinkron dengan tab Output. Tombol **Browse** (`📁`) memilih folder.
- **Progress bar** — menampilkan progress render sebagai persentase dan pesan status (misal "Encoding... 45%").
- **Render Video** — mulai render skrip yang sedang terbuka menggunakan pengaturan output dan render yang telah dikonfigurasi. Selama render, tombol berganti menjadi **Cancel** (styling merah); klik untuk membatalkan. Sebagian kontrol UI di-disable selama render untuk mencegah konflik state.

**Workflow render:** Tombol memicu render single script kecuali batch render sedang aktif. Jika batch render berjalan (dimulai via **Render This Collection), tombol ini menjadi **Cancel Batch** dan menghentikan seluruh queue setelah script saat ini selesai.

### Render Queue Tab

Hanya terlihat selama batch render (Render Collection). Menampilkan progress live compact dari semua skrip yang antri:

- **Stats label** — `Queue: X/Y | OK: N | Failed: M` dimana X adalah selesai+gagal+dibatalkan, Y adalah total.
- **Current script** — menampilkan `collection / script_name [resolution fps duration codec]`
- **Progress bar** — persentase progress per-script dan pesan status (Starting..., Encoding..., Completed, Failed, Cancelled).

Di bawah progress bar ada legend **Render Queue** minimal yang menampilkan stat yang sama. Tab update real-time saat setiap skrip selesai.

Ketika semua skrip selesai, dialog **Batch Render Summary** muncul dengan tabel hasil lengkap (Script, Status, Output/Error, Duration) dan tombol **Copy Report** untuk menyalin ringkasan teks ke clipboard.

## Batch Render (Render This Collection)

Batch render memproses semua skrip dalam koleksi yang dipilih dan semua sub-koleksinya secara rekursif, dengan pengaturan render identik untuk semua.

**Cara memulai:**
1. Pilih koleksi di panel kiri.
2. Klik kanan → **Render This Collection**, atau via menu Collection → **Render This Collection**.
3. Dialog konfirmasi menunjukkan total skrip, preset, duration, format, dan folder output.
4. Klik **Yes** untuk memulai.

**Perilaku:**
- Tool membuat subfolder bernama koleksi di dalam folder output pilihan. Setiap skrip disimpan sebagai `001_script_name.mp4` (penomoran mempertahankan urutan alfabet di setiap level koleksi).
- Semua skrip menggunakan preset, duration, format output, dan folder output yang ditampilkan di bottom Render bar.
- UI otomatis beralih ke tab **Render Queue**. Skrip yang sedang dirender **di-highlight di pohon Collections** (background warna primer) untuk identifikasi mudah.
- Kamu dapat **Cancel** kapan saja via tombol merah **Cancel** di bar bawah. Pembatalan berhenti setelah script saat ini selesai.
- Ketika selesai, dialog **Batch Render Summary** muncul menampilkan status per-script (OK, Failed, Cancelled) dengan timestamp dan snippet error. Klik **Copy Report** untuk menyalin ringkasan plain-text.

Semua render individual menggunakan logic error-fix dan auto-retry yang sama seperti render single.

## AI Features

### Generate Script from Description

Fitur AI inti: deskripsikan video dalam bahasa alami, dan tool menghasilkan komponen Remotion TypeScript yang valid.

- Menggunakan provider AI terkonfigurasi (OpenAI, Gemini, Groq, dll) dengan system prompt yang menerapkan best practices Remotion.
- Retry hingga 5 kali dengan exponential backoff (2s, 4s, 8s, 16s, 32s).
- Mengekstrak kode dari markdown fence (```tsx ... ```) atau respons mentah. Validasi bahwa hasil mengandung keyword `import` atau `React`; gagal jika tidak, retry.
- Berhasil, kode otomatis mengisi editor TypeScript.

### Refine Prompt

Terletak di tab **Generate with AI**. Mengembangkan ide singkat ke prompt terperinci dan terstruktur yang menghasilkan skrip lebih baik. AI rewrite berisi 3–6 kalimat dengan spesifikasi motion, warna, transisi, dan mood. Ini adalah panggilan AI terpisah sebelum generasi.

### Refine Script (AI Code Edit)

Di tab TypeScript, ketik instruksi ke field **Refine** dan klik **Refine** (atau Enter). AI membaca skrip saat ini dan membuat perubahan minimal, ter-target menggunakan blok SEARCH/REPLACE. Hanya lines yang ter-affect yang diganti; sisa skrip tetap sama. Retry hingga 3 kali. Jika semua gagal, dialog **Refine Failed** muncul untuk retry atau cancel.

**Contoh instruksi:**
- `buat teksnya merah`
- `tambahkan fade-out di akhir`
- `ubah easing ke spring`

### Fix Errors (AI Debug)

Ketika render gagal karena error TypeScript atau runtime, dialog **Render Failed** muncul dengan pesan error lengkap. Jika API key AI dikonfigurasi, tombol **Fix Errors** muncul. Klik untuk mengirim skrip beserta error ke AI, yang mencoba memperbaiki kode otomatis menggunakan blok SEARCH/REPLACE. Jika perbaikan AI juga gagal, kamu bisa retry atau edit manual.

## Export dan Save Options

### Export Collection to ZIP

Mengekspor seluruh pohon koleksi (koleksi, sub-koleksi, semua skrip) ke arsip ZIP tunggal. Setiap skrip disimpan sebagai file `.tsx` dengan nama yang sama seperti di database. Hierarki folder di dalam ZIP mirror struktur koleksi kamu. Dialog progress menampilkan status; cancellation didukung. ZIP ditulis ke lokasi yang kamu pilih.

### Save Script as TSX

Mengekspor satu skrip ke file `.tsx` mandiri. Tersedia dari menu Script dan context menu script. Membuka dialog Simpan Berkas standar. Berguna untuk version-control skrip di luar app atau berbagi.

## Tips

- **Keyboard shortcuts:** `Ctrl+Shift+N` untuk koleksi baru, `Ctrl+N` untuk skrip baru, `Ctrl+E` untuk edit skrip.
- **Search cepat:** Gunakan field search di panel Collections untuk filter berdasarkan nama, tag, atau bahkan isi kode di semua skrip.
- **Workflow preset:** Gunakan preset built-in (720p60, 1080p60) untuk kebanyakan kasus. Buat preset Custom hanya jika butuh codec atau quality settings khusus yang cukup berbeda.
- **Batch rendering:** Gunakan **Export to ZIP** dulu untuk backup lokal sebelum batch render besar. Proses batch render menyorot skrip yang sedang dirender di tree, jadi progress mudah dilacak.
- **Preview hot-reload:** Saat server preview berjalan, menyimpan skrip (`Ctrl+S`) memicu hot-reload otomatis. Kamu juga bisa klik **Reload** manual.
- **AI refinement:** Tombol **Refine Prompt** sering menghasilkan hasil lebih baik daripada menulis prompt sendiri. Gunakan meski ide kamu jelas — AI mungkin menambahkan motion detail yang tidak kamu pikirkan.
- **Error recovery:** Jika **Fix Errors** gagal, klik tombol **Retry** di dialog error. AI coba ulang perbaikan dengan skrip yang sudah di-update. Seringkali percobaan kedua atau ketiga berhasil.
